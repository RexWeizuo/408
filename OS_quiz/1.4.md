### ✅ 参考答案与核心解析（供你自查）

1. **启动瞬间**：
   * **0xFFFF0**（BIOS）。BIOS存储在**ROM**中。**（修正）** BIOS 不是操作系统的一部分，它是**固件**，存储在 ROM 中是**非易失性**的，即使断电也不丢失，确保断电后下次开机 CPU 还能找到引导程序。

2. **中断向量表**：
   * 记录：**中断号** -> **中断服务程序的入口地址**。
   * 作用：当键盘敲击事件发生时，键盘发送中断号 -> CPU 根据中断号在内存中查找对应地址 -> 跳转到对应驱动代码执行。

3. **引导顺序**：
   * **MBR -> PBR -> BootMgr -> 操作系统内核**。
   * **（修正）** MBR 不直接加载内核。它的核心功能是**加载并跳转到活动分区的 PBR**。后面再由 PBR 加载 BootMgr，再由 BootMgr 加载内核。

4. **无结构 vs. 模块化**：
   * 无结构弊端：1. 程序错误多，难以调试；2. 程序难以阅读和理解，维护负担重。
   * 模块化关键：**内聚性**（模块内部功能的紧密程度）和**耦合性**（模块之间相互依赖的紧密程度）。高内聚、低耦合是目标。

5. **分层结构**：
   * 原则：**单向依赖**（低层不能调用高层，高层可以调用底层）。
   * **（修正）** 缺点：**层间通信开销大**。每一层之间都要建立通信机制，执行一个操作往往需要自上而下穿越多层，导致系统执行效率降低。

6. **宏内核 vs. 微内核**：
   * **宏内核**：基本调度、中断、文件系统、大部分驱动。优点：效率高；缺点：一个模块崩溃可能导致系统崩溃。
   * **微内核**：基本调度、中断。优点：稳定性高、灵活、易于扩展；缺点：消息传递开销大。
   * **应用场景**：航空航天系统倾向于选择**微内核**（因其高可靠性和稳定性）。

7. **微内核的通信（4次上下文切换）**：
   * **4次切换**：1. 用户态 -> 内核态（发送请求）；2. 内核态 -> 用户态（进入文件服务器）；3. 用户态 -> 内核态（发送响应）；4. 内核态 -> 用户态（返回客户）。
   * **（修正）** 这种频繁的上下文切换和消息复制导致微内核性能低于宏内核。

8. **机制 vs. 策略（厨房例子）**：
   * **机制**：炉灶、冰箱、切菜板等固定设备（内核提供的基础功能）。
   * **策略**：先切菜还是先烧水、放多少调料（用户态服务器中可灵活调整的算法）。

9. **VMM 分类**：
   * 第一类 VMM：**直接运行在裸机上**。效率高、不依赖宿主 OS。
   * 第二类 VMM：**VMware Workstation**。依赖宿主 OS 的资源管理。
   * **（修正）** 第一类 VMM 效率更高，因为它不需要经过宿主 OS 中转，直接由 VMM 接管硬件。

10. **虚拟机特权指令**：
    * **陷入 (Trap)** 到 VMM 中，由 VMM **模拟**执行。这个过程称为“陷入并模拟”。这也是虚拟机性能低于原生系统的原因之一。
